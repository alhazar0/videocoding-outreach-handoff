# 项目与商业目标

## 我们在做什么

VideoCoding 产品尝试帮助创作者完成视频制作与编辑，历史外联主要介绍 talking-head 视频的 B-roll、动态图形、字幕、音乐和音效，也有少量面向知识类视频的文字生成视频邀约。具体能力、当前套餐、时长和效果必须按最新产品核验，历史邮件中的描述不是永久能力承诺。

3000 项目是外联运营系统，并非视频生成产品本身。它连接联系人、邮箱、产品后台和人工决策，让一封邀请能够追溯到完整来往、试用过程、报价与服务问题。

最终业务目的应是：找到内容与产品匹配的创作者，获得可信的实际评估，在双方明确预算、内容和授权条件后形成可衡量的付费合作。每日 750 封曾是业务吞吐目标，并不是“发满就成功”。

## 完整流程

公开渠道发现 → 身份、邮箱与内容匹配 → 最近 30 天活动核验 → 模板与原通道预约 → 窗口和额度内首次联系 → 收信分类 → 完整上下文人工审核 → 自愿试用或先谈商业条件 → 产品使用核验 → 报价条件确认 → 业务批准 → 制作和发布验收 → 效果归因。

前半段已有较完整工具，后半段的预算分配、合同、发布证明、付费广告许可和商业归因尚未形成可靠闭环。不能把收到报价、免费试用、后台账号 active 或候选名单视为合作成交。

## 两条沟通路线

**希望先谈付费条件的创作者**：先说明是否有真实预算、brief、格式、数量、时间和权利范围。没有批准就明确处于探索阶段，尊重对方暂停，不用试用换取报价或反复发码。

**自愿私人评估的创作者**：说明评估独立于付费合作，不需要免费发布。优惠码路线可能绑卡且会自动续费；免绑卡路线则须先核验精确注册账号，并由人工幂等开通。已使用、已拒绝或已开通过的人不能重复发码或 grant。

## 角色与审批

| 工作 | 系统可做 | 必须由负责人决定 |
|---|---|---|
| 发现与去重 | 公开来源、身份/内容/活动核验、排队 | 改变采集范围或限制 |
| 常规回复 | 完整上下文后准确确认、澄清已有诉求 | 费用接受、付款退款、合同、内容许可 |
| 产品试用 | 核验真实账号和历史证据 | 未授权的赠送范围或产品承诺 |
| 产品投诉 | 建立 pending 服务项、暂停推广、记录材料 | 实际账单操作、删除、修复或明确关闭 |
| 发送与恢复 | 原规则内执行、去重、保存不明结果 | 提速、跨通道调额、更换身份、恢复已暂停工作 |

## 交接时必须保留的事实

2026-10-08 至 10-18 曾出现微软发件账号限制，后经管理员解封和一次受控内部实际收件验证恢复。原理由为异常发送模式/可能被盗用，不能从中断言具体投诉原因或确实被盗。随机间隔、逐封发送也不保证免风控。

2026-10-21 用户明确要求停止，后台 23 项 VideoCoding 任务被卸载并禁用，包含 8 个采集进程；dashboard 被保留。服务器恢复不等于重新授权发信。接手的首要任务是理解现状和验证恢复条件，而不是重跑旧 manifest。
