## 三部分必须一起理解

| 交接对象 | 位置与状态 | 用途及限制 |
|---|---|---|
| 应用与后台代码 | 本仓库 app/scripts/build/worker | 可阅读与开发，生产凭证默认关闭；不是全部 VideoCoding 产品后端 |
| 测试、构建与锁定依赖 | tests、package-lock、requirements | 真实结果见 09_VALIDATION，不是全仓通过或干净机器验收 |
| 当前空库结构与历史迁移 | handoff/schema-current.sql、db、drizzle | 当前结构可独立创建；历史 SQL 含旧策略，不批量重放 |
| 原部署模板 | deploy | 说明调度方式；路径和身份已脱敏，不能通配启动 |
| 项目说明与方法 | docs/01、03、04、07、08 | 商业目的、模块、运行、迁移、已知问题 |
| 统计与可复算程序 | docs/02、handoff/metrics.json、analyze_outreach.py | 聚合结果与只读复算；不把未知写成零 |
| 文案与我的建议 | docs/05、06、10 | 历史内容分析与待审草案；建议不是发送授权 |
| 精确联系人、账号、任务排名 | 仓库外私有 creator-details.json 与中文明细 | 可回答谁有真实使用及谁有未结事项，不能公开关联身份 |
| 完整运营与线索数据库 | 仓库外私有一致性快照 | 保留收发、原活动日、去重、DNC、hold、service、grant；凭证清除 |
| 完整已保存轮次证据 | 私有 operations-evidence 与 runtime-analysis | 包含已保存的附件、grant、Sent、未知查证和修复；旧脚本仅归档，不执行 |
| 原始运维脚本与配置 | 私有 runtime-source-reference | 保留脱敏前的本地路径和历史个案保护；不能代替最新数据核验 |
| 暂停证据和保护清单 | 私有 user-pause 证据、protected-state、数据库 | 核对 23 个停用服务、未知和人工保护，不凭模式字段自动恢复 |
| 邮箱、产品、Stripe 凭证 | 不在 Git 或数据包内 | 独立配置与授权；不复制 Keychain、环境密钥或 OAuth refresh token |
| 产品后台与账单依赖 | 仓库外系统 | 外联项目只含客户端；外部 renewalSchedule.js、交易/退款/删除权限未迁入 |
| 当前线上事实 | 本次未联网刷新 | 恢复前另读最新收发和精确产品账号，旧快照不足以执行 |

“完整交接”在这里指把已掌握的代码、证据、保护状态、知识和缺口都明确交付，不表示外部产品服务、付款权限或所有历史附件都已取得。本地保存的附件会进入私有包；没有下载保存的远端媒体只保留引用与读取结论，不能声称已经归档全部媒体。外部依赖未就绪时，学习和开发可以继续，生产恢复不能假装完成。

私有包不是公开仓库的 Release 或附件。管理员按授权范围单独交给同事，并校验其 manifest 和 SHA-256。包内保留个人会话，不要再上传公开 issue、公开 AI 上下文或公开 Git。临时公开过的代码即使后来改私有，也不能撤回已经下载的副本。

## 下载和第一步

```bash
git clone https://github.com/alhazar0/videocoding-outreach-handoff.git
cd videocoding-outreach-handoff
git log -1 --format='%H %s'
```

也可下载仓库 main 分支 ZIP；ZIP 没有 Git 历史。代码仓库有意采用全新的脱敏历史，不继承原仓库中的真实联系人种子和操作记录。

先看 README、AGENTS、本清单和 docs/10，再按 README 阅读顺序理解架构与复盘。仅阅读不需要任何生产密钥。空数据演示使用 3001，避免占用原 3000；所有安装步骤与限制见 docs/04。

## 交接验收

| 检查 | 通过标准 |
|---|---|
| 文件完整性 | Git commit 与交接 manifest 一致，私有包解压后哈希一致 |
| 保护事实 | 同一快照计数、主键与 source manifest 一致；34 初次 unknown 和独立未知回复不丢失 |
| 服务和暂停 | 82 active holds、22 pending service work/17 contact 基线保持；新数据另做差异核验 |
| 开通历史 | 不能把 59 operations 与 83 audit 相加；按产品 ID/幂等 key/确认到期重建 ledger |
| 发送历史 | accepted/unknown 和已确认回复不进入新发送；保留 Message-ID、原通道与原活动日 |
| 只读复算 | 成熟七天 28,912、候选回复 2,920；产品账号去重 240/474 与冻结报告一致 |
| 开发环境 | 干净安装后重跑并记录实际结果，不套用原机器通过数字 |
| 运营授权 | 暂停默认有效；同事得到明确恢复范围后才处理对应线上功能 |
| 外部依赖 | 由负责人提供精确产品/账单接口、权限和凭证，不能从已有字段猜能力 |

复制到多个机器仍是同一个业务时，去重、额度和暂停必须共享。若用来开展新的业务，重新定义产品、身份、批准预算、条款和名单，不继承本项目的历史发送授权。
