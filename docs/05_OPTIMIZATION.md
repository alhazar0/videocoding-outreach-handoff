# 优化顺序与可验证实验

## 优先解决业务闭环

最明显的沟通问题是“付费合作”措辞形成了已有预算和 brief 的预期，而后续只能告知尚未批准。多位创作者已明确先谈条件或跳过试用，相关实名案例在私有交接中。继续增加发送量会放大这种落差。

在下一轮开始前，先把活动分为真实已批准赞助和探索性评估两种。前者要有负责人、预算区间、格式和交付约束；后者首封就说明尚无确定付费项目，允许对方只留报价或暂不参与。报价应进入可搜索的完整条件字段，而不是自动接受。

## P0 先做且不依赖扩量

| 项目 | 具体产物 | 验收 |
|---|---|---|
| 暂停与恢复控制 | 单一运营暂停状态，覆盖所有 sender、router、grant 和 health job | 暂停期间无外发；重启机器仍暂停 |
| 可靠历史迁移 | 发送事实、未知、DNC、hold、service、grant 全量迁移清单 | 精确计数和主键一致；旧 accepted/unknown 无重复 |
| Coupon 事件源 | redemption_id、code、product_user_id、event_at、source、checked_at、状态 | 真实有证据；unknown 不折算成未核销 |
| 付款和投诉 | 17 个联系人的未结服务事项由有权限人员处理 | 单项真实解决证据后人工关闭 |
| 数据质量 | 自动回信标注、渠道和模板快照、分类历史、账号身份映射 | 同一规则可复算且抽样误差可量化 |
| 测试 fixture | 统一现有 schema 创建器，修复 6 项旧 coupon 测试错误 | 完整 Python 测试干净通过且未削弱保护 |

## P1 名单与实验

优先把 AI 工具评测、剪辑教程、talking-head 的真实内容匹配做细；AI & Tech 的整体历史结果更好，但不能只凭类别名批量通过。对小类别不因几个快回复就扩量。

在**已获批的原通道额度内**预先登记随机实验：同类别、同粉丝档、同语言证据、同提供商、同星期的联系人分层，再随机分配两份措辞。随机分组 ID、完整 subject/body SHA-256、发送时间、规则版本和资格证据永久保存。各组使用一致跟进策略。已发送或不明联系人不重入实验。

主要指标设为七天“合格正向回复”：理解产品、明确自愿下一步，或给出可执行的报价条件。拒绝、投诉、自动确认和客服 ticket 单列。次级指标为实际新增完成任务、经验证核销、获批合作和发布验收；反向指标为退订、投诉、投递失败、账号限制和每条回复的人工处理时间。

预先用基线、最小有意义差异和多重比较规则做样本量计划。现有总体 10.1% 不是所有小群体的同一基线；不能看到前 20 个样本领先就宣布胜出。观察窗结束前不要将未回复计为永久不回复。

## P1 工程改进

- 统一 provider submission 状态机：reserved → submitting → accepted / rejected / unknown，所有发送器共用；记录请求阶段、固定 Message-ID 和证据。现在初次 SMTP 有保护，其他历史发送链仍需整体审计。
- 统一 full-context 版本：本地、原提供商、相关账号和附件的快照 ID；检测变更后重新审核，不仅重新算哈希。
- 让队列和业务状态独立：已发送的支持 work 可以继续 pending，但发送 attempt 必须不可重复。
- 将巨大 operations API 拆为联系人、会话、审阅、产品核验、商业条款、服务案例、审计模块；减少多个脚本重复建表和状态漂移。
- 记录字段来源和时间：subscriber/category/language、product checkedAt、quote currency 等。推断值不能冒充本人确认或官方交易。

## P2 商业归因和可复制能力

为创作者发放独立、受控、可撤销的推广标识或 referral ID；与现有自测码分开。区分“创作者自测核销”和“其受众带来的核销”。事件链应是 creator → campaign → placement → click/referral → registration → redemption/payment → refund/chargeback。不能用 shared FREETEST100 回推是谁带来的。

给新同事的 AI 建立两种角色：只读分析/草稿角色可以批量处理统计和建议；发送执行角色只能消费明确批准、精确绑定上下文且未过期的 manifest。批量化的是证据整理、分层、草稿和审计，不是跳过每个收件人的语义与去重核查。

## 不建议的优化

不为了 750 降低内容/身份/活动门槛，不挪原通道额度，不反复试探提供商限制，不向等预算者反复发码，不把活动日期到期当作自动解除 hold。不要把历史产品已完成任务用于反驳收费、取消或退款投诉。
