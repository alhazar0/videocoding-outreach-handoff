# 发送与转化复盘

## 范围和结论

报告日期 2026-11-01。只读本地运营数据库，收信观察截止采用双通道最后同步时间的较早值 **2026-10-20T18:18:57+00:00**，产品最后核验为 **2026-10-20T18:18:48Z**。暂停后没有同步的邮件不在统计内，不能将 11 月 1 日当成新的完整观察终点。

最有依据的优先级是 AI 与科技类；目前证据不足以认定“哪份文案因果最优”或“谁带来的优惠码核销最多”。扩量之前，先补真实预算、试用与核销归因、完整迁移状态和测试可靠性。

表面上 first_contact-v2 为 23.62%，v3 为 21.35%，较高；不能据此把 v2 定为已经验证的最佳文案。

从实际 Sent 的首发邻近记录恢复的主要正文看：v1 与 v3 基本相同；v2 在同一正文中增加了“下载视频源代码、用 vibe coding 工具继续编辑”的一句。legacy_light 较短。版本号、experiment_id 中的 winner 都不是随机实验结果。

对同周、同类型、同提供商且两组各至少 20 人的可比层做加权：v1 与 legacy_light 只有 1 个可比层，回复率约 20.38% 对 16.67%；v1 与 v2 也只有 1 个可比层，约 5.56% 对 24.17%；v2 与 v3 没有足够重叠层。既有选择差异、先后时间、内容匹配、跟进和提供商状态仍未控制。因此只能将 v2 的相关描述作为**待验证假设**，而且产品当前是否支持该承诺必须先核验。

现有数据支持“匹配名单 + 明确产品用途”优先于单纯追求短文案。下一轮以同类、同周、同原通道的随机分组比较，并以合格正向回复、实际完成、投诉和最终合作作为主要结果，不能只优化总回复数。

## Coupon 与真实使用

只有一个统一历史码 FREETEST100，profile 记录给 1,978 人；没有每位创作者独立码，因此无法统计“某位博主的粉丝用码最多”。

- 6,997 个 profile 核销状态 not_checked，代表未知。
- 177 个标记 not_redeemed，代表本地负向标记；还需核验源 API checkedAt 与交易证据。
- 没有 redeemed 记录，代表**系统没有记录到核销证据**，不代表真实核销数为零。
- coupon_redemption_verified_at 在当前 apply_usage 中写入本地同步时间。它不等于 Stripe 原始核销时间，也不能单独证明做过有效的核销检查。
- 240 个 verified、product_outreach_api、completed、非空产品 ID 的账号累计 474 个完成任务；另有 5 个当前查无账号的 profile 残留历史完成数合计 11，已从这一榜单排除。
- 完成任务可能来自手动免卡、既有订阅或其他来源，不等于用了 FREETEST100；不能用 240 / 1,978 直接宣称优惠码转化率。

具体人名、邮箱、产品账号和使用排名见仓库外私有交接。排名靠前的六个账号累计完成数为 9、8、8、8、7、7；其中也有未结服务事项，不能因使用多就继续推广。公开版不关联个人身份与使用或投诉记录。榜单全是截至上次核验的累计数，不是 11 月 1 日实时数据。

## 成交和收入暂时不能证明

联系人 deal_status 只有 4 个 negotiating，其他为 not_started；没有足以确认已批准合作、按合同交付、发布验收、付款或增量收入的完整字段链。不能因此断言现实中完全没有成交，也不能把全部报价计为成交。应建立 campaign、contract、publication、invoice、attribution 等独立记录后再计算 CPA、收入或 ROI。
